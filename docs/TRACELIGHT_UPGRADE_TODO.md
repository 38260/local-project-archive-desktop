## 已确认的需求

1. 首页拖动只改变排列顺序，保留原有分类和状态分组，不设独立的“手动排序”模式。
2. 中文名保留“归迹”，统一展示为“归迹 · tracelight”；英文名称使用小写 `tracelight`。
3. 项目详情新增流程图展示，自动发现 `flowchart.png` 等相关图片，支持选择与替换。
4. 替换图片保存在档案数据目录，保留项目原图，不向原项目目录写入文件。
5. 重新布局详情页启动面板，允许修改、删去启动项。
6. 修复编辑档案时拖选文字、鼠标移出弹窗后松手导致弹窗关闭的问题。
7. 用户审阅计划后开始实现；每完成一个小功能，更新本文件并单独提交 Git；最后进行整体验证后交付验收。

## 当前实现与工作区依据

- 基线：`main`，`2b8fda1`，应用版本 `1.10.0`；Python/FastAPI + SQLite + Vue 3 静态页面 + pywebview 桌面壳。
- 已跟踪文件没有未提交改动。原有未跟踪内容为 `archify_workflows/` 与宣传视频，视为用户资产，保留且不纳入本次提交。
- 首页 `dashboard.js` 的 `moveProject()` 会强制切到“手动排序”；`displayGroups()` 随之变为“置顶项目 / 项目”，不再保留状态分组。
- 启动面板已有检测、拖动排序、自定义项增删改和运行历史。虽然数据计算支持混排，模板仍把自定义项与自动检测项拆成两块；自动项只有“转存为自定义”。
- 项目已有图片预览、截图上传、项目内文件读取接口，可复用展示与上传流程。流程图识别和独立的选择/替换记录尚不存在。
- 编辑档案遮罩使用 `@click.self` 关闭弹窗；这是本次误关闭的重点排查位置，尚需真实操作复现才能确认根因。
- 当前中文品牌仍为“归迹拾光”，英文品牌、安装产物多处为 `Tracelight`；前端共享组件、事件和本地偏好使用 `Lpa` / `lpa-` 命名。

## T2：首页拖动保留分组

### 方案

- 默认视图继续按原有状态分组；搜索和筛选继续保持现有结果展示方式。
- 拖动直接保存用户排列，不切换到另一种视图，不修改项目的 `status`、`category`、`pinned` 或档案更新时间。
- 默认分组视图仅允许同一状态组内移动，并保持置顶优先边界。跨组拖动不修改分类，也不把卡片临时移入其他组。
- 搜索/筛选结果里的拖动同样不能跨状态或置顶边界；隐藏项目仍保留在完整顺序中，清除筛选后不会丢顺序。
- 去掉“手动排序”选项。保留名称、最近更新等已有规则，作为“整理顺序”操作：选择规则时重新排列，之后可直接拖动覆盖排列，无需选择手动模式。
- 兼容已有 `ui.project_order`；旧“手动排序”偏好升级后自然应用到各组。新项目追加到对应组内，已有卡片保持相对位置。
- 保留拖动手柄、键盘移动和保存失败回退。

### 修改范围

`app/static/js/dashboard.js`、`app/static/dashboard.html`、排序设置的默认值/校验、`tools/test_dashboard_order.cjs`、必要样式和文档。

### 验收

- 拖动前后“进行中 / 已完成 / 暂停 / 归档”等组标题和成员不变。
- 刷新、重新打开应用后保留组内顺序；分类、状态、置顶和更新时间未被拖动修改。
- 跨组拖动、筛选后拖动、新增项目、键盘移动和保存失败均有回归用例。
- 界面没有独立“手动排序”选项；自动整理后可立即继续拖动。

## T3：流程图自动识别与展示

### 方案

- 详情正文新增“流程图”面板，并加入左侧导航，放在基础/Git 信息之后、启动面板之前。
- 按文件名识别 `flowchart`、`flow-chart`、`flow_chart`、`workflow`、`流程图`、`工作流` 等关键词；识别大小写不同的扩展名。
- 首轮支持 PNG、JPG/JPEG、WebP、GIF、BMP、SVG；以图片展示，不解析绘图工程文件。
- 搜索根目录及有限深度的文档/图片子目录，跳过依赖、Git 和构建垃圾目录，限制遍历数量。建议初始上限为 3 层、2000 条文件记录。
- 多张图片按“根目录精确 flowchart 文件名 → 相关命名 → 路径深度 → 稳定文件名顺序”给出候选；默认展示第一张并标明相对路径。
- 复用现有图片预览与项目文件接口，显示缩略预览、点击放大；无图片时提供清楚的空状态和选择入口。
- 图片访问校验真实路径边界，包括符号链接/目录联接，防止读取项目范围外文件。SVG 以图片方式展示，并限制脚本与外部资源执行。

### 修改范围

`app/services/parser.py` 或小型专用识别函数、`app/routers/projects.py`、`app/static/project.html`、`app/static/js/project.js`、`app/static/css/style.css`、流程图识别回归检查。

### 验收

- 根目录 `flowchart.png`、子目录 `workflow.svg`、中文文件名、大小写扩展名和多图候选均能正确识别。
- 无图、目录丢失、文件损坏、图片被移动时有明确提示，详情其他面板仍可使用。
- 大目录不会无限扫描；越界路径、符号链接越界和不支持格式有相应检查。
- 浅色/深色、宽屏/窄屏均可查看完整图片。

## T4：流程图选择与替换

### 方案

- “更换流程图”支持选择已发现的项目内图片，或从本机上传图片。
- 用户指定的图片优先于自动候选。上传存入 `data/flowcharts/` 等档案专用目录，原项目文件保留。
- 复用已安装的图片处理能力做格式/内容校验，单张沿用 5MB 上限；替换失败时继续显示之前的有效图片。
- 为项目补充最小的流程图选择记录，采用可兼容旧库的增量字段；修改前留备份，不删除旧列/数据。
- 提供“恢复自动识别”，清除手动覆盖后重新展示自动候选；原项目路径更新或重新解析不覆盖用户上传图。
- 项目删除时只清理该档案管理的图片。候选源图不删除、不改写。
- 选择记录随档案 JSON 导出/导入；本轮沿用截图的媒体保留方式，JSON 与数据库备份不打包图片二进制，跨机器迁移需连同档案媒体目录保留。
- 单项目 HTML 导出嵌入当前流程图，导出文件可离线查看。

### 修改范围

`app/db.py`、`app/models.py`、流程图 API、媒体文件管理、前端选择/上传交互、`app/main.py` 导入导出、单项目 HTML 导出和相应回归检查。

### 验收

- 选择候选、上传替换、刷新、重启、恢复自动识别均符合优先级。
- 两个项目的图片互不串用；替换失败、超限或伪造图片不会破坏之前的记录。
- 原项目图片的内容和修改时间不变。
- 旧库升级、JSON 选择记录恢复、HTML 离线展示均通过；媒体迁移限制在文档和交付说明中写明。

## T6：全部启动项的修改与移除

### 方案

- 自定义项继续使用现有编辑/删除 API，补齐统一列表交互。
- 编辑自动检测项时，预填名称、命令、工作目录和运行方式；保存为自定义覆盖项，并记住原自动项的内容指纹，避免修改命令后原建议又出现。

### 2026-10-11：T7 弹窗拖选越界误关闭（已完成）

- 修复：`common.js` 新增共享助手 `tlMaskPress` / `tlMaskRelease`（并注入 TL_HELPERS 供模板使用），配对检查 mousedown/mouseup 的起点与终点——只有一次完整的遮罩点击才关闭；内部开始的拖选不关闭，从遮罩开始拖进弹窗也不关闭。
- 覆盖全部受影响调用点：首页（手动录入 / 批量扫描 / 当日提交）、详情页（文档查看器 / 编辑档案 / 启动项表单）、设置弹窗、confirmDialog。取消 / 保存 / Esc / 焦点陷阱与正常点击空白关闭行为不变。
