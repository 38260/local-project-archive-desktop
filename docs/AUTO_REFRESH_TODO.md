# 自动更新 · 实施与验收

> 目标：进入页面、回到应用时后台更新采集数据，先显示已有内容，更新完成后局部替换。
> 原则：复用现有解析器、不整页重载、草稿零丢失、旧结果不回填。

## 场景与预期行为

| 场景 | 计划行为 |
| --- | --- |
| 打开项目详情、切换项目 | 自动更新当前项目 |
| 打开首页 | 后台分批更新已收录项目，首屏正常显示 |
| 从其他程序切回来、最小化或托盘恢复 | 更新当前页面相关数据 |
| 连续切换窗口 | 合并重复请求，同一项目 30 秒冷却 |
| 手动「重新解析」 | 保留，可跳过冷却立即执行 |

自动更新覆盖：技术栈、文件统计、项目简介、Git 摘要；详情页同时重新读取 README、目录树、提交记录和图表。
判断依据是**真实解析结果**（遍历 + git），不单凭根目录 mtime，避免漏掉子目录变化。

## 保护规则

1. 自动刷新只更新采集数据；保留手动标签、描述、笔记、变更日志与自定义配置（启动项顺序/流程图选择）。
2. 刷新期间修改路径、删除项目或切换页面，旧结果不得回填。
3. 不整页重载；正常更新用轻量状态提示，失败提供重试。
4. 自动与手动任务共享并发控制，避免同时解析、重复写入。
5. 自动刷新不改变档案 `updated_at`（首页「最近更新」排序不被后台任务搅动）。

## R1 · 后端统一刷新入口

**新增**
- `app/services/refresh.py`：单项目刷新（`_do_refresh`）、按项目锁、30 秒冷却、
  同项目 in-flight 合并、任务表（`job_id` 轮询）、`refresh_now()` 同步入口。
- `app/routers/refresh.py`：`POST /api/refresh`、`GET /api/refresh/{job_id}`、`GET /api/refresh/status`。
- `app/models.py`：`RefreshRequest`（ids / force / source）。

**语义**
- `source=auto`：只写 `auto_meta` / `fs_created` / `fs_modified` / 丢失标记；
  **不动** `tags`、`description`、笔记、变更日志、启动项与流程图偏好，**不动** `updated_at`。
- `source=manual`：额外合并技术栈标签并刷新 `updated_at`（沿用原「重新解析」行为）。
- 写回语句带 `AND path=?`：刷新期间改路径或删除项目时 `rowcount=0`，结果标记 `stale` 并丢弃。
- 解析失败不写库，上一份有效 `auto_meta` 原样保留；路径丢失只更新丢失标记。
- 手动「重新解析」与「全部重新解析」改为调用 `refresh_now()` / 复用同一把项目锁，
  自动与手动任务不会同时解析同一项目。

**验收（2026-10-21）**
- 工具：`tools/test_auto_refresh.py`（源码与数据全隔离，临时项目 + 隔离 SQLite）。
- 结果：**34 项断言全部通过，0 失败**。覆盖：
  1. 自动刷新写入 `auto_meta`，`updated_at` / 手填标签 / 描述 / 笔记全部保持不变；
  2. 冷却期内再请求 → `skipped`，`force=true` 可跳过；
  3. README 简介、嵌套目录增删、新增 git 提交、技术栈识别都能被刷新捕获；
  4. 刷新进行中重复请求 → 合并到同一 `job_id`；
  5. 路径丢失 → `is_lost=1` 且保留旧 `auto_meta`；路径恢复 → 自动复活；
  6. 刷新期间改路径 / 删除项目 → 结果 `stale`（删除时 `ok=false`），旧数据未被覆盖；
  7. 手动刷新合并自动标签并更新 `updated_at`，手填标签保留；
  8. 空 ids → `noop`，未知项目 → `missing`，未知任务 → 404；
  9. 批量刷新（首页场景）`total/done/ok` 与 `changed_ids` 正确。
- 遗留：无。临时目录在 Windows 上偶发「删除延迟」告警，重试即可，不影响数据隔离。

## R2 · 详情页自动更新

**触发**
- 进入详情页（首屏渲染完成后）→ 后台刷新当前项目；
- `visibilitychange`（回到前台）与 `window.focus` → 300ms 去抖合并；
- 桌面壳 `desktop.py` 在 `shown` / `restored` 事件后调用 `window.tlOnWindowResume()`，
  覆盖最小化恢复与托盘恢复。

**局部替换**
- 完成后重新拉取一次详情，只替换采集字段（`auto_meta` / `fs_*` / `is_lost` / 标签与简介派生值），
  再静默重载 README、目录树、流程图、提交记录、提交构成与热力图。
- `loadCommits(quiet)` / `loadCommitStats(quiet)`：不显示骨架屏、不清空用户筛选与展开状态。
- 不调用 `loadLaunch()`：启动项顺序/默认项等编辑态原样保留。

**草稿保护**
- 描述有未保存改动时不覆盖 `description`，也不更新 `descBaseline` / 预览，
  草稿依旧标记为「未保存」（`descDirty` 保持 true）。
- 笔记草稿（`noteDraft`）、日志草稿（`logDraft` + 标题/日期）、编辑中的既有条目全部不触碰。

**竞态与失败**
- 切换项目（`projectId` 变化）或页面卸载（`_disposed`）时，轮询立即放弃，结果不回填；
- 任务失败显示一条轻量错误条 + 「重试」按钮，页面已有内容不受影响；
- 网络层错误文案转换为「无法连接本地服务，请确认程序仍在运行」。

**验收（2026-10-21）**
- 脚本：`.workbuddy/tmp/verify-autorefresh-detail.py` + `verify-autorefresh-detail.mjs`
  （隔离源码与数据库，临时 git 项目，无头 Chrome 断言）。
- 结果：**22 项断言全部通过**。覆盖：
  1. 进入页面自动刷新；外部改 README + 嵌套新增文件 + 新提交后，简介/文件统计/提交徽章全部更新；
  2. 页面未整页重载（同一文档，钩子仍在）；
  3. 描述 / 笔记 / 日志草稿在刷新后原样保留，描述仍标记未保存；
  4. 启动项对象未被重建（编辑态不丢）；
  5. 刷新期间切换项目 → 新页面数据属于新项目，旧结果未回填；
  6. 连续 5 次 focus 只发出 1 个刷新请求（去抖 + 冷却）；
  7. 阻断刷新接口 → 错误条 + 重试按钮出现，页面内容仍在；恢复后重试成功。

## R3 · 首页自动更新

**触发与批量**
- 进入首页（首屏渲染完成后）、`visibilitychange` / `focus`（400ms 去抖合并）、
  桌面壳 `tlOnWindowResume()`。
- 一次任务提交全部已收录项目 id（上限 500），后端 4 路并发处理；
  前端每 800ms 轮询进度，状态条显示 `done/total`。

**局部替换**
- 仅在 `job.ok > 0` 时重拉 `/api/projects` 替换 `projects/stats/statuses`（不进 loading，不闪骨架屏）；
- 仅在 `changed_ids` 非空时重拉热力图与最近提交；
- 搜索词、状态/标签/分类筛选、快捷筛选、排序方式、手动拖动顺序全部不动。

**滚动位置**
- 数据替换与热力图重排会触发浏览器「滚动锚定」，统一在刷新前后关闭锚定并
  在下一帧 + 80ms 各校正一次，把 `window.scrollY` 拉回刷新前的位置。

**验收（2026-10-21）**
- 脚本：`.workbuddy/tmp/verify-autorefresh-home.py` + `verify-autorefresh-home.mjs`。
- 结果：**21 项断言全部通过**。覆盖：
  1. 首屏 3 张卡片正常渲染，首次批量刷新结束后状态条收敛；
  2. 外部新增提交 + 改 README 后，卡片「最近提交」与简介同步更新，卡片顺序不变；
  3. 搜索命中 1 项时刷新 → 搜索词与筛选结果保持；
  4. 拖动排序后刷新 → 顺序与 `ui.project_order` 保持；
  5. 刷新前后滚动位置 119 → 119（修复前会被滚动锚定推到 161）；
  6. 连续 5 次 focus 只发出 1 个刷新请求；
  7. 阻断刷新接口 → 错误条 + 重试按钮，列表仍可用；恢复后重试成功。

**用户列出的场景覆盖**

- 新增提交 → 卡片最近提交、详情提交记录/构成同步；
- README 修改 → 简介与 README 正文重读；
- 嵌套文件增删 → 文件统计与目录树更新；
- 路径丢失恢复 → 标记丢失并保留旧数据，路径修回后自动复活；
- 草稿保护 → 描述/笔记/日志/启动项在刷新后原样保留；
- 快速切换 → 旧结果丢弃、首页滚动与拖动顺序保持。

**桌面 WebView2 恢复验证**

- 已验证：副本隔离启动（独立数据目录、独立互斥体与窗口标题）、窗口创建、`SW_MINIMIZE` 最小化、
  `POST /api/show-window`（与托盘「显示窗口」同一 `bring_to_front`）返回成功、窗口从最小化恢复。
- 未稳定通过：窗口内页面的自动刷新断言。本机 WebView2 对 `127.0.0.1` 的静态资源请求会被系统代理
  拦截（同端口用 `curl` 直连正常，WebView2 侧请求不到服务端），导致页面脚本未执行、无 `/api/refresh` 调用；
  该现象与代码无关，换到无代理/已把 localhost 列入直连的环境即可复现完整链路。
- 替代验证：浏览器端已断言 `window.tlOnWindowResume` **存在且调用后会发起刷新**（详情页 24 项中的一项），
  桌面壳侧在 `window.events.shown / restored` 后通过 `evaluate_js` 调用同一个钩子，接口契约一致。
- 手动复核步骤（1 分钟）：启动桌面版 → 打开任一项目详情 → 在外部修改该项目 README → 最小化窗口 →
  点托盘「显示窗口」→ 页面顶部出现「正在后台更新采集数据…」，结束后简介随之变化。

**结论**：接口层与浏览器端全部自动化通过；桌面端「窗口恢复 → 前端刷新」的桥接代码路径已核对并有等价断言，
真实 WebView2 的端到端自动化受本机代理环境限制，留待干净环境复核。
