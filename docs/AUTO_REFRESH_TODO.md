# 自动更新 · 实施与验收

> 目标：进入页面、回到应用时后台更新采集数据，先显示已有内容，更新完成后局部替换。
> 原则：复用现有解析器、不整页重载、草稿零丢失、旧结果不回填。

## 场景与预期行为

| 场景 | 计划行为 |
| --- | --- |
| 打开项目详情、切换项目 | 自动更新当前项目 |
| 打开首页 | 后台分批更新已收录项目，首屏正常显示 |
| 从其他程序切回来、最小化或托盘恢复 | 更新当前页面相关数据 |
| 连续切换窗口 | 合并重复请求，同一项目 30 秒冷却 |
| 手动「重新解析」 | 保留，可跳过冷却立即执行 |

自动更新覆盖：技术栈、文件统计、项目简介、Git 摘要；详情页同时重新读取 README、目录树、提交记录和图表。
判断依据是**真实解析结果**（遍历 + git），不单凭根目录 mtime，避免漏掉子目录变化。

## 保护规则

1. 自动刷新只更新采集数据；保留手动标签、描述、笔记、变更日志与自定义配置（启动项顺序/流程图选择）。
2. 刷新期间修改路径、删除项目或切换页面，旧结果不得回填。
3. 不整页重载；正常更新用轻量状态提示，失败提供重试。
4. 自动与手动任务共享并发控制，避免同时解析、重复写入。
5. 自动刷新不改变档案 `updated_at`（首页「最近更新」排序不被后台任务搅动）。

## R1 · 后端统一刷新入口

**新增**
- `app/services/refresh.py`：单项目刷新（`_do_refresh`）、按项目锁、30 秒冷却、
  同项目 in-flight 合并、任务表（`job_id` 轮询）、`refresh_now()` 同步入口。
- `app/routers/refresh.py`：`POST /api/refresh`、`GET /api/refresh/{job_id}`、`GET /api/refresh/status`。
- `app/models.py`：`RefreshRequest`（ids / force / source）。

**语义**
- `source=auto`：只写 `auto_meta` / `fs_created` / `fs_modified` / 丢失标记；
  **不动** `tags`、`description`、笔记、变更日志、启动项与流程图偏好，**不动** `updated_at`。
- `source=manual`：额外合并技术栈标签并刷新 `updated_at`（沿用原「重新解析」行为）。
- 写回语句带 `AND path=?`：刷新期间改路径或删除项目时 `rowcount=0`，结果标记 `stale` 并丢弃。
- 解析失败不写库，上一份有效 `auto_meta` 原样保留；路径丢失只更新丢失标记。
- 手动「重新解析」与「全部重新解析」改为调用 `refresh_now()` / 复用同一把项目锁，
  自动与手动任务不会同时解析同一项目。

**验收（2026-10-21）**
- 工具：`tools/test_auto_refresh.py`（源码与数据全隔离，临时项目 + 隔离 SQLite）。
- 结果：**34 项断言全部通过，0 失败**。覆盖：
  1. 自动刷新写入 `auto_meta`，`updated_at` / 手填标签 / 描述 / 笔记全部保持不变；
  2. 冷却期内再请求 → `skipped`，`force=true` 可跳过；
  3. README 简介、嵌套目录增删、新增 git 提交、技术栈识别都能被刷新捕获；
  4. 刷新进行中重复请求 → 合并到同一 `job_id`；
  5. 路径丢失 → `is_lost=1` 且保留旧 `auto_meta`；路径恢复 → 自动复活；
  6. 刷新期间改路径 / 删除项目 → 结果 `stale`（删除时 `ok=false`），旧数据未被覆盖；
  7. 手动刷新合并自动标签并更新 `updated_at`，手填标签保留；
  8. 空 ids → `noop`，未知项目 → `missing`，未知任务 → 404；
  9. 批量刷新（首页场景）`total/done/ok` 与 `changed_ids` 正确。
- 遗留：无。临时目录在 Windows 上偶发「删除延迟」告警，重试即可，不影响数据隔离。
