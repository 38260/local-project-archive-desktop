## 规则与验收

- 只读被收录仓库；不改仓库 Git 配置、提交或历史，不联网识别 fork。
- 邮箱按完整作者邮箱匹配，忽略大小写；不按作者姓名或提交者邮箱匹配。
- 未配置邮箱时「仅本人」返回空数据并提示设置，不回退到全部作者。
- 首页默认仅本人，相同完整提交哈希跨项目只计一次；当日明细保留所有关联项目入口。
- 详情默认仅本人，切换同时影响列表、月柱状图和构成分析；基础信息仍标明仓库总数和贡献者。
- 已有详情 API 不传 authors 时仍返回全部作者，保持已有调用兼容。
- 作者筛选在条数限制之前执行，计数与列表使用同一作者条件。
- 用临时真实 Git 仓库覆盖：纯 fork、本人与他人同名、多邮箱、正则特殊字符、重复副本、没有匹配提交、空仓库与读取失败。
- 接口、浏览器、整体冒烟测试使用隔离数据；本轮源码交付，安装包与安装生命周期验证另行记录。

## 用户验收步骤

1. 从本仓库运行 `start.bat`，打开终端实际打印的地址；本轮交付源码，现有安装版 EXE 还不包含此改动。源码数据位于本仓库 `data/`，与安装版用户目录中的档案分开，必要时用现有导出/导入功能准备验收数据。
2. 打开「设置 → 通用 → 我的 Git 邮箱」，填写本人常用、旧邮箱及 GitHub 隐私邮箱，每行一个，点击「保存 Git 邮箱」。以 Git 提交里的作者邮箱为准，不以 GitHub 用户名或当前提交者身份为准。
3. 收录一个只有上游历史、没有本人提交的 fork：首页不增加个人贡献，详情「仅本人」提示无匹配；切换「全部作者」可看到上游完整历史。
4. 打开有本人提交的项目，切换作者范围，检查提交列表、每月提交量与构成分析同时更新，刷新后保留选择。构成分析默认排除合并提交，计数可能少于包含合并提交的列表总数。
5. 再收录同一仓库的另一个副本：首页贡献不重复增加；点击热力图当天，唯一提交下的「也在」可跳到另一项目。
6. 清空邮箱后保存：首页和详情本人视图应提示设置，不能重新计入全部作者；完整仓库历史仍可切换查看。
