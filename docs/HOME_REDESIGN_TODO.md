## 1. 上次打开

当前卡片使用 `fs_modified` 显示磁盘修改时间；`updated_at` 是档案更新；`/api/projects/recent` 按最近提交等信息选择最近开发项目。这些字段都不能当作上次打开时间。

建议卡片底部独立显示带时钟图标的 `上次打开：今天`、`上次打开：昨天`、`上次打开：7 天前`。保留磁盘修改信息，通过不同标签明确含义。悬停与键盘聚焦均可查看完整本地日期和时间。

建议统计口径：用户主动进入项目详情，或通过归迹成功请求系统打开编辑器/文件夹时，记录一次；后台刷新、扫描、复制路径、预取和失败的打开请求不记录。该口径是本轮设计建议。

- 使用独立的 `last_opened_at` 字段持久化，初始为空；不从修改时间推测历史访问。
- “今天”“昨天”“N 天前”按用户本地日历日期计算，跨午夜后更新；旧项目显示“尚无打开记录”。
- 系统打开只表示系统已接受请求，不能声称已经检测到编辑器界面出现；应用外部打开行为不在记录范围内。
- 新增“最近打开”排序入口；沿用置顶、状态分组、手动排列的现有规则，一键整理后仍可拖动。

## 2. 左侧快速导航

建议增加默认宽约 208px、可以收起的固定侧栏，内容区域同步保留足够卡片宽度。

- 快捷入口：全部项目、最近打开、已置顶。最近打开只包含有记录的项目，并按打开时间排序；已置顶只筛选置顶项目。
- 项目分类：复用已有 `category`，动态列出前端、后端、桌面应用、AI / 研究、工具脚本等已有值和“未分类”；不创建另一套分类体系。
- 图中类别名称仅为示例，不要求迁移用户现有类别。数量按当前快捷入口、状态、搜索、标签及废弃项可见性计算，不因当前选中的类别把其他类别计数归零。
- 点击类别直接筛选列表；当前项高亮并展示可移除筛选条件；不修改项目分类，不重置手动顺序。类别导航替代宽屏的重复分类下拉。
- 宽屏常驻；较窄窗口收起为图标或抽屉；键盘可以访问，选中状态不只依赖颜色。

## 3. 热力图新方向：本周拾光

把年度小格子替换成一块紧凑的“近 7 天项目进展”面板，回答“最近推进了什么”。本周拾光是模块名称，实际滚动窗口明确标为“近 7 天”，避免误解为自然周。

| 区域 | 内容 | 交互 |
| --- | --- | --- |
| 进展摘要 | 本人提交次数、有提交的项目数、活跃天数 | 查看提交明细 |
| 每日节奏 | 最近 7 个本地日期的提交柱状图，今天有清晰标记 | 点击有提交的日期复用当日提交弹窗；悬停/聚焦显示数量 |
| 最近推进 | 提交最多的 3 个项目及提交数，剩余项目合并为“其他项目” | 项目名进入详情 |

- 沿用“仅本人作者邮箱”和同一提交跨项目去重规则；图中数字不能解释为工时或效率评分。
- 演示数据：32 次提交、5 个项目、4 个活跃日；每日提交为 `0, 6, 8, 0, 10, 8, 0`，日期为 10/16～10/22。
- 演示项目分布：Tracelight 18、WindowAnchor 9、SkillManager 3、其他 2 个项目合计 2，总计 32。
- 面板可折叠并记住用户选择；项目卡片应出现在第一屏。原始提交查看能力在详情/明细入口保留。
- 没有本人邮箱时引导设置；近 7 天无提交时显示空状态；读取失败时明确数据不完整，不把失败伪装为零提交。
- 不用访问次数填充 Git 活动，也不根据提交数推断投入时长。
